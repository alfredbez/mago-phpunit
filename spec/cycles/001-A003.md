# Cycle 001: assertion function key presence

## Decision and evidence

PHPUNIT-A003 closes the public function-call gap without changing method-call
semantics. The pinned PHPStan public test in the catalogue expects a key-presence
postcondition for `PHPUnit\Framework\assertArrayHasKey`. PHPUnit runtime tests
confirm successful and failing calls, including null-valued entries. No analyzer
implementation was copied. Alfred authorized using the existing PHP SDK.

The original regression produced three offset warnings instead of one on Mago
1.58.2 with PHPUnit 12.5.40. The expanded fixture produced seven string-offset
warnings and one integer-offset warning before the fix. After the fix, four
string-offset warnings remain intentionally, with no integer-offset warning.

The new provider uses an exact function target and delegates to the existing
method provider. A separate adapter is needed because the SDK's method and
function interfaces use the same `getTargets()` method with different target
types. There is no second implementation of the assertion semantics.

## Negative and mutation controls

The positive cases use literal string and integer keys and reordered named
arguments. The controls retain warnings for an unasserted read, another optional
key, a variable key, and a different function with the same short name. The
nullable-return function retains both return errors. PHPUnit's two native
named-argument-policy diagnostics remain in enabled and disabled runs.

Four isolated mutations each made the A003 diagnostic check fail:

| Mutation | Observed failure |
| --- | --- |
| Remove function registration | Seven string-offset warnings and one integer-offset warning return |
| Replace HasKey with HasNonnullEntryForKey | Both required nullable-return diagnostics disappear |
| Remove integer-key support | Integer-offset warning returns |
| Target the unrelated same-named function | Six string-offset warnings and one integer-offset warning remain |

The mutation runner first verifies a green baseline and requires an A003-specific
failure. Its initial stdout/stderr capture used independent file offsets, which
overwrote failure text. Redirecting stderr to stdout fixed the runner; all four
mutations were rerun and killed. Mutants never modified the working checkout.

# Cycle 003: named provider rows and dependencies

PHPUNIT-D004 covers closed, non-empty named provider rows with same-class
`#[Depends]`. The runtime fixture from cycle 002 passes on PHPUnit 10.5.66 and
fails on 11.5.57, 12.5.42 and 13.4.5 because a positional dependency result
follows a named argument during unpacking. That observation applies to the
fixture, not every possible row shape.

The hook has no reliable PHPUnit-major signal in its current implementation.
Rather than assume a version from an unrelated class, it skips
provider diagnostics for named rows with one or more same-class Depends
attributes. This avoids applying named-argument checks that can be wrong on
10.5, but does not diagnose the observed 11–13 runtime error. Positional rows
with Depends and named rows without Depends retain their existing checks. Other
dependency attributes, annotations and dependency-result types are outside this
cycle.

The D004 fixture and catalogue entry were added before the hook change. On PHP
8.4.27, PHPUnit 12.5.40 and Mago 1.58.2, the catalogue validator passed and the
analyzer test failed with five provider issues instead of one. After the hook
change, the suite passes with the single expected missing-parameter diagnostic
for a named row without Depends. The fixture also covers an unknown key and a
key that names a different parameter, preventing the existing named checks from
silently surviving on uncertain rows. Disabling extensions emits no provider
diagnostics for the fixture.

On PHP 8.4.27 the matrix passes PHPUnit 10.5, 11.5, 12 and 13. The matrix runs
the analyzer checks and green runtime suite, not the separately failing runtime
fixture. Exact installed versions and command output are recorded in the job
report. A reliable version signal and broader runtime cases remain open before
adding version-specific diagnostics.
